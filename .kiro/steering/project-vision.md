# 專案核心框架（每次對話都要遵守）

## 一句話定位
「別人做的是幼兒園風險評分，我們做的是『AI 稽查官』——用審計界抓弊案的鑑識會計方法算出可解釋的風險分數，再讓生成式 AI 產出稽查建議，讓每個稽查員的產能放大十倍。」

## 這是什麼比賽
2026 新北市 AI 智慧城市黑客松競賽 / 教育局組
題目：小小守護員 Smart Watchdog — AI × 鑑識會計，打造教保機構智慧風險預警管理系統。
決賽 2026/9/12-13，30 小時內交件。限用 AWS Bedrock 基礎模型。

## 系統要做的三件事
1. 抓資料：整合幼兒園公開資料（財報、裁罰紀錄、收費、評鑑、網路輿情）
2. 算風險：用鑑識會計方法給每間園一個可解釋的風險分數
3. 做介面：網頁儀表板，讓稽查員一眼看出哪幾間要優先查

## 三大差異化武器（絕不能偏離）
1. **鑑識會計（最強護城河）**：班佛定律(Benford's Law)抓數字造假、財務比率交叉勾稽（每幼兒單位成本、人事費占比、收支比）、跨年度趨勢突變偵測。90% 隊伍會忽略「鑑識會計」四個字，這是我們的護城河。
2. **可解釋白盒子分數**：風險分數必須拆成明確分項（財務異常/裁罰/評鑑/輿情），每項有權重，能攤開看「87分 = 財務40 + 裁罰30 + 輿情17」，用雷達圖呈現。政府敢用的前提是可解釋。禁止做成黑盒子。
3. **AI 生成稽查建議**：Bedrock 的價值在「把數字翻譯成稽查員看得懂的話 + 給稽查建議」，不是拿來算分數。算分數用規則和統計（可解釋），AI 用來生成報告（降低人力負擔）。

## 加分功能：風險地圖（稽查行動最後一哩路）
把高風險園在地圖上用紅/黃/綠標出來，點下去看園所名稱+風險分+問題，讓稽查員排路線精準投放人力。
**技術決策：用 Leaflet + OpenStreetMap，不用 Google Maps**（免費、不用金鑰、避免金鑰誤傳GitHub違規、開源專業度更高）。地址轉座標用免費 Nominatim geocoding。地址來源=全國教保資訊網基本資料。

## 評分權重（所有決策都要對齊）
- 技術可行性 30%：鑑識會計有學理根據 + 白盒子分數 + 清楚 AWS 架構
- 資料應用性 30%：真的整合財報+裁罰+收費+輿情，做交叉勾稽
- 完成度 20%：儀表板能跑、能 Demo
- 主題契合度 20%：扣緊「鑑識會計」「事前預警」「降低人力」關鍵字

## 資料集實況（重要，已實際確認）
- 公校決算書(112/113/114年度)：有文字層，可程式抽取。第5冊含市立幼兒園決算(編號13601起)，是財務異常偵測的黃金資料。
- 非營利園財報(110~113學年度約132份)：除封面外內頁是掃描影像，無文字層，需 OCR / AWS Textract / Bedrock 多模態才能抽數字。這是門檻也是機會。
- 需自行補：全國教保資訊網(裁罰/評鑑/基本資料/收費)、新北市幼兒教育資源網。裁罰紀錄是風險標籤來源。

## 實作優先順序（30小時策略）
1. 先做 MVP：挑15-20間公校幼兒園(決算書可直接抽) → 鑑識會計指標 → 風險分數 → 儀表板。不靠OCR，確保跑得出來。
2. 接裁罰紀錄當標籤，證明高分園確實較常被裁罰。
3. 用Bedrock對1-2份非營利園掃描財報做抽取，證明架構可擴展 + 生成風險報告。
4. 小樣本NLP輿情分析當亮點。
5. 全程強調「抽樣展示，架構可規模化到全部機構」。
