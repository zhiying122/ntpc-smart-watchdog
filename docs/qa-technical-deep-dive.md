## 2. 鑑識會計六層怎麼算（技術核心，`src/forensic.py`）

系統對每間園跑 `analyze()`，算出下面所有指標，全部**可解釋、有公式**。

### 2.1 班佛定律（Benford's Law）
- **原理**：自然財務數字首位數為 1 的機率 = log10(1+1/1) ≈ 30.1%，遞減至 9 約 4.6%。
- **算法**：`benford_mad()` 取逐筆明細金額的首位數，算 **MAD 平均絕對偏差**。
  審計門檻：<0.006 高度吻合、0.006–0.012 可接受、0.012–0.015 邊緣、>0.015 可疑。
- **統計檢定**：`benford_chi_square()` 另算卡方（自由度 8、α=0.05 臨界值 15.507）與 p-value。
- **專業判斷**：只用在**跨數量級的逐筆明細**（min_n=30 才算），不用在彙總數字。
- **大樣本陷阱（主動講）**：明細多時卡方會過度敏感，所以**主判用 MAD 的組內相對排名**
  （`benford_score` = MAD 百分位×100），卡方只當輔助。**不宣稱造假，只排優先序。**
- 林口實例：`benford_mad = 0.03534`（>0.015，偏離較大），組內排名換算 `benford_score = 53`。

### 2.2 Beneish M-Score 改良版
- `beneish_lite()`。原版 8 變數有 5 個（銷貨/應收/槓桿）在非營利園不成立。
- **保留 3 個可轉移維度**：
  - EGDI 收支成長背離 = 支出成長率 − 收入成長率（權重 0.5）
  - SGI 收入成長指數 = 收入成長率（權重 0.25）
  - TATA 應計偏離 = 賸餘/收入（權重 0.25）
- 誠實命名「改良版」，不宣稱用原版。林口 `beneish_score = 28.1`。

### 2.3 Altman Z'' 在地化困境分
- `altman_z2_lite()`。**誠實揭露**：決算資料沒有資產負債表（總資產/負債/權益），
  硬套原版 Z'' = 用不存在的資料。所以用**可得欄位建三個代理比率**：
  - X1' 營運結餘率 = 賸餘/收入
  - X2' 基金厚度 = 期末基金餘額/收入
  - X3' 收支效率 = (收入−支出)/收入
- 代理判別式 Z2' = 3.3·X1' + 1.2·X2' + 6.7·X3'，用困境/安全界線（1.10/2.60）映射 0–100。
- 對應**舞弊三角的「壓力」構面**。林口 `altman_score = 100`（進困境區，這是財務分主推力）。

### 2.4 孤立森林（Isolation Forest）+ SHAP
- `isolation_forest_scores()`，用 sklearn `IsolationForest`（200 棵樹），
  異常點路徑短 → 分數高。SHAP 解釋前 3 大異常特徵（`iforest_explain`）。
- **避免重複計分（主動講、專業）**：只餵**其他層沒單獨計分**的維度——
  `tuition_income_ratio`（學雜費占收入比）、`income_yoy_pct`（收入年增率）。
  收支比、支出年增、班佛、Beneish 已在別層算過，不再餵一次。
- 林口 `iforest_score = 24.5`。

### 2.5 財務比率交叉勾稽 + IQR
- `compute_ratios()` 算收支比、學雜費占收入比；`flag_outliers()` 用 **IQR 法**
  （Q1−1.5·IQR、Q3+1.5·IQR）抓離群。
- **拿全體公立園當基準**＝審計的**同儕比較**（PCAOB AS 2305 實質分析程序背書）。
  公立園同質性高，是天然可比同儕群體。

### 2.6 基金餘額勾稽（最貼近鑑識官實務）
- `fund_reconciliation()`（同期）+ `fund_continuity()`（跨年度）。
- 恆等式：**期末基金餘額 = 期初 + 本期賸餘 − 解繳公庫 ± 調整**。
- 跨年度：本年期初 = 上年期末（更難造假，只在年度真正相鄰時比對，避免缺年假陽性）。
- **不對稱設計**：勾稽一致→加 0 分（不動基礎分）；不一致→財務分向上加成（最多 +15）。
- 誠實揭露：22 間市立園雙層勾稽**全部一致**（符合正式決算文件預期），
  抓弊價值會在帳務參差的非營利園顯現。林口 `fund_recon_score = 0`、`fund_continuity_score = 0`。

## 3. 風險總分怎麼組（白盒子，`src/risk_score.py`）

### 3.1 頂層四分項加權（forensic 檔）
```
總分 = 財務×0.45 + 裁罰×0.30 + 評鑑×0.15 + 輿情×0.10
```

### 3.2 財務分內部七層（`score_financial`）
```
財務 = 班佛×0.22 + Beneish×0.17 + Altman×0.15 + 孤立森林×0.22
     + 收支比×0.08 + 跨年度突變×0.08 + 賸餘短絀率×0.08
     + 基金勾稽不對稱加成（不一致才 +，最多 +15）
```
- 收支比分：收支比 >1 時 (ratio−1)×500，超支 20% 即滿分。
- 賸餘短絀率：短絀達收入 10% 即滿分。

### 3.3 林口 55.6 分完整拆解（背起來）

| 分項 | 原始分 | 權重 | 貢獻 |
|---|---|---|---|
| 財務 | 45.7 | 0.45 | **20.6** |
| 裁罰 | 90.0 | 0.30 | **27.0** |
| 評鑑 | 40（乙）| 0.15 | **6.0** |
| 輿情 | 20（中性）| 0.10 | **2.0** |
| **總分** | | | **55.6** |

財務 45.7 從哪來：Altman 100×0.15 是主力，加班佛 53×0.22、孤立森林 24.5×0.22、
Beneish 28.1×0.17、收支比 1.0728 超支約 36 分×0.08、短絀 7.3% 約 73 分×0.08，
基金勾稽一致加 0。

### 3.4 裁罰分（`score_penalty` + `penalty_nlp` + 破窗）
- **不是純看次數**，看**違規性質嚴重度**。收費類基底 80，2 次遞增到 90。
  林口是「超收幼生與收費違規」2 次 → `score_penalty = 90`。
- **破窗效應**（`broken_window.py`，有逐筆日期時啟用）：
  分數 = min(100, 頻率放大 × Σ 嚴重度權重 × 時效衰減)
  - 嚴重度：輕微 3 / 中度 6 / 重大 12
  - 時效衰減：0.5^(距今月數/半衰期)，半衰期預設 18 個月（近期違規權重高）
  - 頻率放大：1 + 0.15×(違規數−1)
  - 學理：破窗理論（Keizer et al., Science 2008）+ 動態再犯風險（Yukhnenko, Oxford）
  - 無逐筆明細時**優雅退回**嚴重度計分（向後相容、不造假日期）。

### 3.5 評鑑分（`score_eval`）
優=0、甲=10、良=20、乙=40、中=50、丙=70、待改進=90、不通過=100。缺資料=中性 30。
林口評鑑「乙」→ 40。

### 3.6 輿情分（`score_sentiment`）
- 負面比例 neg_ratio × 100，缺資料中性 20。
- **貢獻上限 15 分**（score() 內 clamp）；查無新聞中性不放大（責任 AI）。
- 林口查無指名新聞 → neg_ratio=NaN → 中性 20 → ×0.10 = 2。

### 3.7 風險分級（兩套並存，前端只顯示一套）
- **主用 `risk_level`**：**分機構類型各自做百分位**（前 15% 高、次 35% 中、其餘低）。
  為什麼分類型：公校有班佛分項、非營利園沒有，混在一起排會系統性壓低非營利園、
  導致「整類機構被隱形」。分開排才公平（同儕比較精神）。
- `risk_level_abs`：絕對門檻（≥60 高、≥35 中），僅對照、不顯示。
- 林口 `risk_level = 高`（在公校群組的前段）。

### 3.8 雙評分檔（R26，創意 3）
- `resolve_scoring_profile()` 確定性判定：有財報→forensic（四分項）；
  無獨立財報（國小附幼）→ behavioral（裁罰0.5/評鑑0.3/輿情0.2，財務不計入）。
- 目前資料都是 forensic；接附幼時自動切 behavioral，畫面標示「無獨立財報」。

## 4. 裁罰怎麼對到機構（責任 AI 關鍵，`src/penalty_match.py`）

**問題**：裁罰 JSON 的鍵多是**個人姓名**（行為人/負責人），不是機構名。
把「張三」對到「XX 幼兒園」本質不確定（同名、負責人異動）。

**解法：信心分級，不確定的絕不當事實**
- **HIGH**：裁罰對象名 = 機構名（正規化後相等），或 = 機構負責人且該名唯一對應一間。
- **MEDIUM**：= 負責人但對應多間機構（無法唯一判定）。
- **LOW**：部分相符。
- **只有 HIGH 才計入「確認裁罰數」**（`confirmed_penalty_counts`），
  MEDIUM/LOW 標「待人工確認」不計分。
- 還會**去重**：同一裁罰（相同對象+日期+法條+處分）不重複計數，避免虛增風險。

> QA 金句：「我們不會把不確定的比對當事實去冤枉機構——這是政府系統的底線。」

## 5. AI 怎麼用（`src/ai_report.py`，責任 AI 兩道關卡）

- **定位**：Bedrock **只生成白話稽查建議，不算分**。模型是
  `us.anthropic.claude-sonnet-4-5-20250929-v1:0`，區域 us-west-2。
- **流程**：把單園關鍵指標（風險分、班佛 MAD、Beneish、收支比、支出年增、裁罰次數、
  基金勾稽結論）組成 prompt → Claude 產 120–200 字建議。
- **責任 AI 兩道關卡**：
  1. **提示詞負向約束**：明令只能做「發現異常/排序/解釋/提供證據/建議方向」五件事，
     嚴禁宣稱違法/舞弊/犯罪。
  2. **輸出後過濾** `sanitize_output()`：即使模型不慎產出「違法/舞弊/詐欺…」等字樣，
     一律中和為「需進一步查核之疑慮」。兩條路徑（Bedrock + 範本）都過濾。
- **保底**：偵測不到憑證或呼叫失敗 → **自動退回規則式範本** `generate_fallback()`，
  **demo 一定有東西出來**。憑證偵測同時支援環境變數（本機）與 IAM Role（EC2）。
- Copilot 問答 `answer()`：只用該機構實際資料回答，關鍵陳述附來源，資料不足明講不杜撰。

## 6. 怎麼證明模型有效（`src/validate.py`）

以「**是否被裁罰**」為真實標籤驗證風險分：
- **AUC-ROC = 0.906**（>0.9 優異）
- **Recall = 1.0**（沒漏抓任何被裁罰的園，符合稽查「寧嚴勿漏」）
- Precision 較低是刻意的「寧嚴勿漏」策略
- 相關係數：風險分 vs 裁罰次數正相關
- **可當場重現**：`python -m src.validate`

**權重敏感度分析**（`src/sensitivity.py`）：5 組不同權重重算，
Spearman ρ ≥ 0.97、前三名（林口/深坑/三芝）不變 → 結論不靠主觀調權重。

  AWS 優先用 **IAM Role**（免金鑰落地）；上 GitHub 前跑 `python scripts/check_secrets.py`。
- **部署**：一台 EC2、systemd 兩服務（`watchdog-gov`/`watchdog-public`）、S3 存資料、
  GitHub Actions self-hosted runner push→main 自動部署、健康檢查頁監控。

## 8. QA 快問快答（最可能被追問，直接背）

**Q：資料到底哪來的？**
A：公校決算書是命題方給的 PDF、有文字層直接抽；機構基本資料和全國裁罰是串接
g0v 開源專案整理自全國教保資訊網的 JSON（誠實標二手來源）；新聞 RSS 和 PTT 公開板
是真實爬取、每筆附原文連結。官方全量裁罰/評鑑/收費我們誠實標「未確認」。

**Q：林口 55.6 怎麼算？**
A：裁罰 27（2 次收費違規）+ 財務 20.6（Altman 困境滿分+入不敷出+短絀 7.3%）
+ 評鑑 6（乙等）+ 輿情 2（查無新聞給中性）= 55.6，每分可追到底層數字。

**Q：班佛定律小樣本準嗎？**
A：所以我們每園至少 30 筆明細才算，且知道大樣本卡方過度敏感，主判用 MAD 相對排名、
卡方只輔助，不宣稱造假只排優先序。

**Q：權重憑什麼？**
A：敏感度分析 5 組權重重算 Spearman ≥0.97、前三名不變，結論對權重不敏感。

**Q：Altman 不是要資產負債表嗎？你哪來的？**
A：誠實說——決算沒有資產負債表，硬套原版是用不存在的資料。我們用可得欄位建三個
代理比率、明確標示 proxy，保留 Altman 的困境判別精神，取得完整財報後可升級原版。

**Q：AI 會不會亂講、冤枉園所？**
A：兩道關卡——提示詞禁止違法宣稱 + 輸出後過濾中和斷言字樣；AI 只生成建議不算分；
裁罰比對只採 HIGH 信心、不確定標待人工確認；家長端資料層移除風險分。

**Q：Bedrock 掛了怎麼辦？**
A：自動退回規則式範本，demo 一定有輸出，這本身證明系統穩健。

**Q：為什麼沒用 RDS/Redis？**
A：MVP 資料走檔案契約、無需外部 DB；架構已預留，正式部署改接 data.gov.tw 官方 API
與資料庫，不需改動風險引擎與 UI。

**Q：這能規模化到全市/全國嗎？**
A：能。目前抽樣 60 間展示；資料連接器介面固定，改指向 data.gov.tw 端點即可全量，
風險引擎與前端不用改。
