# 部署與資安說明書

**系統**：Fiscalint 教保機構智慧風險預警管理系統
**適用對象**：新北市政府教育局 / 資訊局（系統移交、上架審查、資安評估用）
**文件性質**：政府級系統移交必備文件，說明系統組成、部署方式、資安控制、
權限架構與維運監控。

---

## 1. 系統組成（兩系統切分）

本平台採**網路區隔（Network Segmentation）**設計，為兩個獨立系統：

| 系統 | 進入點 | 使用者 | 內容 | 網域（生產） |
|------|--------|--------|------|------------|
| 公務後台 | `app/主頁.py` | 教育局／稽查員 | 風險分數、鑑識分析、AI 稽查報告、派工、資料整合、健康檢查 | 內網 / GSN 政府網 |
| 公眾查詢網 | `public/公開查詢.py` | 一般民眾／家長 | 去識別化公開資訊（基本資料、收費、公開評鑑） | 公開網際網路 |

兩系統各自為獨立執行程序，生產環境應部署於獨立網域與主機，僅共用唯讀的
「鑑識風險中台」（`src/` 引擎 + 資料層），公眾網於資料層即去識別化投影。

---

## 2. 部署方式

### 2.1 環境需求

- Python 3（依 `requirements.txt`）。
- 作業系統：Windows / Linux 皆可。
- 無需 GPU；無需外部資料庫（資料以檔案契約為主，可擴充至 DB）。

### 2.2 安裝

```
pip install -r requirements.txt
copy .env.example .env      # 填入必要環境變數（如 AWS Bedrock 金鑰，選用）
```

### 2.3 啟動（開發／Demo）

公務後台與公眾網使用不同 port，展示網路區隔：

```
python -m streamlit run app/主頁.py --server.port 8501
python -m streamlit run public/公開查詢.py --server.port 8502
```

### 2.4 生產部署建議

- 以反向代理（Nginx / IIS）分別對應兩系統，套用各自的網域與存取控制。
- 公務後台限制於內網 / VPN / GSN；公眾網對外開放但唯讀、無風險資料。
- 以行程管理器（systemd / Windows 服務 / supervisor）常駐 Streamlit 行程。
- 以排程器每日呼叫 `src.live_source.load_live_dataset()` 更新動態資料
  （見資料介接與備援計畫書）。

## 3. 資安控制（Security by Design）

### 3.1 身分驗證與存取控制（RBAC）

- 公務後台採 RBAC 雙層授權：
  - 第一層（UI 導覽）：`permissions.get_role_navigation` 依角色過濾可見頁面。
  - 第二層（資料層）：`auth.require_role` 於每頁渲染前守衛；即使直接輸入
    頁面網址，角色不符亦被擋下並記稽核軌跡。
- 生產環境對接「新北市政府單一登入（SSO）」與「行動自然人憑證（TW FidO）」，
  登入後由後端解析職權代碼自動分流，使用者無法自選角色。競賽為驗證環境，
  以帳密模擬 SSO 身分交換（已於登入頁誠實標示）。

### 3.2 資料層授權（權限在資料層擋，非前端隱藏）

- `permissions.authorize_dataframe(df, role)` 依角色投影資料：
  - 政府／稽查員：全欄位可見。
  - 家長／公眾網：實際移除所有 `risk_*` / `score_*` 及排序衍生欄位，回傳的
    資料**根本不含** `risk_total`——非前端算出再隱藏。

### 3.3 稽核軌跡（Audit Trail）

- 登入、登出、存取遭拒、檢視、風險判定、回饋等關鍵操作皆寫入 append-only
  稽核軌跡（`src/audit.py`），僅可新增不可竄改，依時間查詢。

### 3.4 機密管理

- 所有金鑰置於 `.env`（已 gitignore），程式以 `os.environ` 讀取，禁止寫死。
- 上傳前執行 `python scripts/check_secrets.py` 掃描，顯示 `[OK]` 方可上傳。
- 動態資料源為免金鑰唯讀 HTTPS GET，不外傳任何專案資料或個資。

### 3.5 外部連線最小化

- 系統唯一的外部連線為動態資料連接器對官方開放資料源的唯讀 GET，且含
  逾時保護與離線備援；無其他對外連線。
- 健康檢查僅檢視本地狀態，不對外部來源即時發網路請求。

### 3.6 責任 AI（Responsible AI）

- 系統僅發現異常、排序、解釋、提供證據、建議稽查方向；不判定犯罪／舞弊／
  違法，不以單一訊號貼標籤。每則風險陳述附「風險不等於違法」聲明。
- 裁罰-機構比對採信心分級，僅高信心比對建議計入，不確定比對標「待人工
  確認」不直接計分（`src/penalty_match.py`）。

## 4. 維運監控（Operability）

- 「系統健康檢查」頁（`app/pages/8_health.py`）提供：契約資料新鮮度、動態
  資料源快取狀態、核心引擎模組可載入性、資料完整性，整體狀態一眼可見。
- 動態資料源即時連線狀態於「資料整合中心」按下同步時回報（即時／備援）。

---

## 5. 資料保護與個資

- 家長／公眾端一律去識別化，不揭露風險分數或內部欄位。
- 內部風險資料僅授權公務角色可見，並受資料層授權與稽核軌跡控管。
- 裁罰資料涉及個人姓名者，系統以信心分級處理比對，避免因不確定比對而
  對機構或個人造成不當標記。

---

## 6. 品質保證

- 全系統經四層驗證：語法（compileall）、型別／lint（IDE 診斷）、單元／
  屬性測試（pytest + Hypothesis）、執行期（Streamlit AppTest 端到端）。
- 屬性測試以 Hypothesis 實作，每個正確性性質對應單一屬性測試。
- 動態資料源可用性、裁罰比對正確性均經真實資料實測驗證。
