# OCR 方案：非營利園掃描財報怎麼處理

## 問題
非營利園財報（110~113 學年度約 132 份 PDF）除了封面，內頁是**掃描影像、沒有文字層**，程式無法直接讀文字。公校決算書則有文字層，可直接抽。

## 為什麼這是機會而非障礙
多數隊伍會卡在這裡放棄非營利園資料，只做公校。我們把 OCR 做出來，資料涵蓋面就贏過別人，直接拉高「資料應用性 30%」。

## 三個技術選項（由易到專業）

### 選項 A：本地 OCR（Tesseract）— 免費、離線、適合先驗證
流程：PDF 頁面 → 轉圖片(pdf2image/PyMuPDF) → Tesseract OCR(中文) → 文字 → 正則抽數字
- 優點：免費、不用網路、開發階段可快速試
- 缺點：中文財報表格辨識率一般，數字容易錯
- 套件：`pytesseract`, `pdf2image` 或 `PyMuPDF(fitz)`，需另裝 Tesseract 引擎與中文語言包

### 選項 B：AWS Textract — 比賽主場、專門解表格（推薦主力）
Textract 的 `AnalyzeDocument` 有 TABLES 功能，專門辨識表格結構，對財報這種表格資料辨識率遠高於 Tesseract。
- 優點：表格結構化輸出（知道哪格對哪格）、辨識率高、是 AWS 服務（比賽加分）
- 缺點：要錢（但額度小、抽樣展示夠用）、要設 AWS 憑證
- 流程：PDF → S3 → Textract AnalyzeDocument(TABLES) → 結構化 JSON → 抽財務數字

### 選項 C：Bedrock 多模態（Claude 3 視覺）— 最有 AI 亮點
把財報頁面圖片直接餵給 Bedrock 的 Claude 視覺模型，用 prompt 叫它「讀出這張財報的收入、支出、人事費並回傳 JSON」。
- 優點：一步到位（OCR+理解+結構化）、展現生成式 AI 應用（比賽評分項）、能處理複雜版面
- 缺點：要錢、大量頁面成本較高
- 適合：Demo 展示「AI 直接讀掃描財報」的驚豔效果

## 建議策略（對齊 30 小時）
1. **主力資料走公校決算書**（有文字層，穩），先把 MVP 跑出來。
2. **非營利園用選項 C（Bedrock 多模態）抽 1-2 份做 Demo**，展示「我們的架構連掃描檔都能處理，且用了生成式 AI」。講清楚「抽樣展示，可規模化到 132 份」。
3. 選項 B(Textract) 當簡報架構圖裡的「正式量產方案」寫進去，展現技術可行性。

## 對應架構圖
```
非營利園掃描PDF → S3 → [Bedrock多模態 或 Textract TABLES] → 結構化財務JSON → 併入風險引擎
公校決算PDF(有文字層) → pdfplumber 直接抽 → 結構化財務JSON → 併入風險引擎
```
兩條路最後匯流到同一個風險評分引擎。
